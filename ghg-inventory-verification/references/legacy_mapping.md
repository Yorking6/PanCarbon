# 原型抽象化对照（仅开发期参考）

本文件说明如何把一次性交付脚本抽象成通用 Skill。**不含任何组织名称、绝对路径、排放因子数值或报告年份**；原型文件由开发者在本地指定，绝不随 Skill 分发。

## 1. 可抽象复用的结构

| 原型中的形态 | 抽象后 | 处理方式 |
|---|---|---|
| 源表转储工具（按主体前缀命名文本文件） | `extractors/excel_ledger.py` 的读表工具 | 主体前缀改为 `entities[].id`；文本转储改为结构化 `RawRecord` |
| 读表、取行、去千分位、取前导数字等清洗函数 | 通用 `clean / rows_of / num` 工具 | 保留算法，去掉所有字段名与企业语义 |
| 因子/运输/差旅/通勤字典 | `factor_library.schema.json` | **只保留字典的键结构，删除全部数值** |
| 物料名/承运商关键词映射因子 | `method_factor.py` 的规则表 | 规则由 `methodology.per_source` 注入，不内置关键词表 |
| 清册逐格公式转储文本 | `inventory_layout.md` 的公式模式 | 抽象为 `tco2e = ad * ef * gwp / scale`；坐标改为锚点 |
| openpyxl 建表工具（写入、清表、列宽、样式常量） | `build_inventory.py` 通用写入器 | 保留工具函数；样式值移到 `inventory_template.json` |
| 公式引擎重算并与计算结果比对 | Stage 7 双轨对账 | 保留思路，改为对 `results.json` 而非固定单元格 |
| 数据质量与缺口说明 sheet（缺口、方法变更、总量三段） | `quality_gaps` sheet | 保留结构，内容全部运行时注入 |
| 固定话术段落、签署表、结束标记 | `phrases.json` | 保留「话术与数值解耦」原则，文字由使用者提供 |

## 2. 必须丢弃的内容

- 所有硬编码的因子值、汇率、GWP 数值、电网因子、热值、密度、价格；
- 所有绝对路径、输出文件名、模板复制目标；
- 具体组织名、厂区简称、人名、地址、邮箱、审核员姓名；
- 单年假设（以某年清册为模板复制、固定报告年、固定基准年）；
- 68 键式的一次性活动数据字典与主体专属字段；
- 损坏外链、历史草稿表、被 `superseded` 的旧口径结果；
- 硬编码数字的绘图脚本与对比网页结论；
- 「合计行取行内最大数值」「取某列最大值」等启发式抽数；
- 模板里残留的旧年份文字、示例行、案例数据。

## 3. 抽象化改写顺序

1. 把「值」外移到 `org_config` / `factor_library` / `activity_ledger` 的运行时注入；
2. 把「表头与坐标」外移到 `inventory_template.json` 的锚点与字段键；
3. 把「主体标识」外移到 `entities[].id`；
4. 把「方法判断」改为带 `note` 的规则对象，由配置注入；
5. 把「合计」改成显式字段，由公式与勾稽规则计算；
6. 把「结论性文字」改为占位符 + 人工签核；
7. 每个改写点补一条 `validation_rules.md` 规则，防止事故复现。

## 4. 开发期离线对账（不随包分发）

- 在 Skill 包**之外**的开发目录放置一次性对账脚本，读取原型中间产物作为期望值，验证抽象后引擎能复现同结构结果。
- 对账脚本、期望值副本与日志都不进入 `scripts/` / `references/` / `assets/` / `tests/fixtures/`。
- `tests/fixtures/` 只能包含完全虚构的组织、假因子与假凭证；可用 `ghg audit` 复核纯抽象。
- 对账结论只用于调整引擎结构，不把任何历史数字写回 Skill。
